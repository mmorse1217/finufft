## Design Decisions

- **Diagnosis from deduplicated counters, not the flamegraph.** The v11av source CSVs show
  the 16-cell accumulation at 37.6% / 48.2% of scan samples, only 6.4 / 4.1 of 32 lanes
  active per accumulation instruction, and 2.0-2.25x the useful FFMA count because the fixed
  body updates zero-weight cells. The z lane-group shift was another ~8-10% in nested
  `FSEL`/`ISETP`. Shared loads were not bandwidth-bound; SoA/packing had changed the wrong
  thing.
- **Contiguous z row.** Three zero pre-pads (slots 18-20; 18 is also the y post-pad) and the
  existing post-pads (27-29) let a lane load its four z values from
  `21 + support_coefficient_offset_z - local_cell_offset_z`. The z select chain is gone.
- **Free contiguous y row.** The x post-pad at slot 11 is also the y pre-pad, so y loads
  from `12 + support_coefficient_offset_y - local_cell_offset_y` with no extra shared memory.
- **Strength-scaled accumulation.** Four real and four imaginary `strength*z` factors are
  formed once per lane group, then one FMA per cell: `16 FMUL + 32 FFMA` -> `8 FMUL +
  32 FFMA` (48 -> 40 instructions). This changes FP32 multiplication association, not the
  polynomial; `relL2` stays in the noise floor.
- **Keep 5 blocks, not 6.** `VALUES_PER_POINT` is 30, so the maximum 5-block batches are
  13 (per-warp) / 53 (block-shared). Shared memory is 12,696 / 12,936 B; registers are 96 /
  95; no spills. A 31-float row breaks the 8-byte `int2` metadata load; a 32-float row
  makes every row start on the same shared bank and is slower.
- **Do not force more splits.** Uniform `nsplit` 2/4 is slower; clustered 56 remains the
  knee (16/32/56/64 = 11.89/11.33/**11.23**/11.36 ms).
- **Rejected follow-ups:** xy-scaling instead of z (worse), scoped scaling (tied),
  three-point scan unroll (clustered worse), explicit `float2` staging stores (neutral),
  all-row-contiguous layouts (misaligned or bank-aliased). The 2-point scan remains.

## Trade-offs

- **Multiplication association changes.** `(s*z)*xy` instead of `s*(xy*z)` is not bitwise
  identical, but `relL2` remains within the FP32 reordering noise floor (5.64e-7 / 2.26e-7 /
  7.34e-8). It is not a kernel/polynomial approximation.
- **Smaller batches.** STAGE 28 -> 30 costs one point per per-warp batch and three per
  block batch. The scan savings dominate; the staging/loop overhead grows slightly.
- **No 6-block occupancy.** The scan still holds 16 `float2` accumulators plus the scan
  working set; 96 registers / 5 blocks remains the best balance. The 31/32-float-row
  variants confirm that alignment and bank rotation matter more than another select.
- **Remaining scan waste is structural.** The fixed 16-cell body still does ~2x the useful
  cell updates; only ~40 of 512 cells per warp region are covered on average. Reducing that
  needs a different ownership/geometry or shared accumulation, not another packing tweak.
- **Uniform total is now preprocessing-bound.** At 14.45 ms total, preprocess + metadata is
  ~3.54 ms (24%); the random-permutation payload gather is ~1.35 ms of that.
- **Method-3 timing variance is high across processes.** Use the 4-run medians for the
  v11ay/v11av comparison; the per-process `speedup_vs_m3` ratio is noisy.
