# Handoff: cuFINUFFT Morton output-owned spreading wayfinder

## Goal

Wayfind toward a faster cuFINUFFT CUDA spread path: decide whether Morton-sorted, output-cell-owned spreading should replace the current atomic-based spread for 3D type-1 FP32, and settle the integration design if it wins.

The wayfinder destination is a measured go/no-go on the Quadro T1000, plus integration scope for the type-2 inverse and FP64 if the answer is go.

## Design Decisions

- **Success gate:** at least 20% lower method-3 spread-stage time on both mandatory `N=1e6` workloads — uniform and clustered. No mandatory workload may regress more than 5%. Total preprocessing + spread must be within 5% of method 3’s total. End-to-end type-1 may regress at most 2% before default-on is blocked.
- **Measurement:** median of 5 runs after 2 warm-ups, CUDA events around the spread kernel, identical inputs and fine grid. Nsight is for counters/stalls, not timing.
- **Experiment sequence:** Experiment A (Cartesian bins + output-cell ownership) first, then Experiment B (Morton + output ownership), both time-boxed. If A shows no benefit, B is still worth one run.
- **Scope:** type-1 FP32 only for the go/no-go. Type 2 and FP64 are integration-scope decisions after a go. Type 3, CPU, non-CUDA backends, multi-GPU, and 1D/2D prototypes are out of scope.
- **Evidence bar:** T1000 is sufficient for the prototype go/no-go. The sm_75 scalar-atomic / 4 GB / small-L2 generalization risk is recorded as a caveat, not a gate.
- **Ownership model:** use method 4’s exact division of the fine grid into outer bins (its output regions) as the ownership model; do not copy method 4’s ghost index entries. Method 3 remains the benchmark.
- **Geometry:** `binsize = 8` per dimension; tile `16×16×8`; one CUDA threadblock per tile; 256 threads; 8 cells/thread; clamp partial edge tiles. Optional sweep: `8³` and `16³` tiles.
- **Morton key:** 64-bit key, x-lowest bit interleaving. `bits = ceil(log2(max nbins_i))`, `end_bit = 3·bits`. Wrap bin coordinates modulo `nbins_i` before keying. No ghost copies.
- **Lookup:** dense table for the first prototype, behind a small interface. Sparse backend is deferred; binary search is not the chosen fallback. A better sparse data structure is a future decision.
- **Kernel-support boundary:** expand each tile by `ceil(ns/2) = 3` cells. Because `binsize = 8 > 3`, one adjacent bin layer suffices. Keep enumeration/overlap branch-light; use the Horner kernel path.
- **Benchmark fine grids:** mandatory `64³` dense (`N=1e6`) and `128³` sparse (`N=1e5`); optional `256³`/`512³`. `1024³` was illustrative, not a test case.
- **Vocabulary:** `bin` = point grouping; `tile` = output region; `local subgrid` = shared-memory buffer holding the tile; `CUDA threadblock`; avoid unqualified “block”. Use `kernel support`, not “halo”. “Destination” is reserved for wayfinder maps.

## Trade-offs

- **Dense lookup first:** simple and fast for `64³`/`128³`, but O(number of bins) and wrong for large sparse grids. Sparse backend deferred.
- **T1000-only evidence:** fast to decide, but sm_75 complex atomics are two scalar operations while sm_90+ can use vector atomics. The relative win may not generalize.
- **Method 3 cluster baseline is strong:** clustering is faster than uniform at `M=1e6` (`15.75 ms` vs `18.67 ms`). The 20% gate is therefore ≤`14.94 ms` uniform and ≤`12.60 ms` clustered.
- **Branch-light vs fixed-box:** a fixed expanded-bin box avoids data-dependent branches but does more work; a bounded overlap loop does less work but has loop branches. Not yet measured.
- **Historical terminology:** some closed tickets and research notes still use old terms (`halo`, `tap`, `source bin`, `output tile`, `B`). `docs/GLOSSARY.md` is canonical.
- **One ticket per session:** the baseline closed in this session; the prototype should start in a new wayfinder session.

## Design Decisions

- **Geometry (v5+):** tile `16×16×8`, 128-thread blocks (4 warps), warp region `8×8×8`, lane owns `2×2×4` = 16 cells in registers, one non-atomic store per cell. Chosen over 8 cells/thread and over 256-thread/`16×16×16` tiles by measurement.
- **Preprocessing is selectable:** Cartesian counting sort (`prep=0`: atomic histogram + per-bin atomic scatter) or CUB `DeviceRadixSort::SortPairs` of (bin, point index) + payload gather + start-mark/scan (`prep=1`, default).
- **Batch across x-runs, not per bin:** warp walks its bin cube as contiguous x-runs, so batches are 16 points at any `qb`. This is what makes `qb=1` (reread 5.36) usable.
- **Double-buffered staging:** next batch's global loads are issued before the current batch is scanned; two 24-float buffers per warp still fit 12 KB/block.
- **Split warp regions for clustered inputs:** each tile is launched `nsplit` times; split `s` takes every `nsplit`-th batch of every bin; each split writes a full partial grid, `kernel_sum_splits` reduces. `nsplit` = smallest power of two with `active_warps * nsplit ≥ 512`, capped 8 (uniform 512→1, clustered 64→8).
- **`dim_support` kept as selects, not bit masks.** Masked form measured +7.6% (uniform 23.30 vs 21.65 ms); SASS control-flow instruction count identical (159), so masks add ALU without removing branches. Documented in code.
- **Fold-per-dimension broadcast rejected** (B1): +31% (28.0 vs 21.4 ms) due to the `__shfl_sync` dependency stall; the six lanes already fold in lockstep.
- **`__launch_bounds__(128,6)` rejected:** 80 regs with 32 B spill stores, only ~1.4% faster.
- Chrome trace is a **synthetic PC-sample attribution**, not a call stack: depth 4 `kernel → inlined function → helper → source line`; stall reasons are event `args`, not frames. Older hand-built traces with stall frames were deleted.

## Trade-offs

- `qb` and preprocessing choice are **distribution-dependent**: uniform best at `qb=1` + radix; clustered/sparse best at `qb=4`, and clustered prefers the counting sort (1.7 ms vs 2.5 ms radix). No single config is best for all.
- 16 cells/thread cuts rereads but raises registers (94–95) and lowers occupancy (5 blocks × 4 warps = 20 warps/SM); 8 cells/thread was slower overall.
- Splitting adds a reduction kernel and partial-grid memory (`nsplit × nf`), only used when `nsplit > 1`; uniform pays nothing.
- The gather trades method-3-style local accumulation efficiency for single-writer stores; per-point scan/staging remains the tax.
