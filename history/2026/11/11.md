### What each experiment changed

**`zskip`: per-point z rejection.**
Move the z loads to the beginning of the accumulation loop.
Test whether any real or imaginary z weight in the thread's group is nonzero.
Skip the point when all those weights are zero.
The branch is warp-uniform because a warp owns one z slice.
This helped uniform input, but dense time increased substantially. Reverted.

**`unroll4`: accumulation-loop unrolling.**
Restore the baseline and add `#pragma unroll 4` to the staged-point loop.
The measurements did not show a useful consistent benefit. Reverted.

**`runs`: contiguous x-bin batching.**
Adjacent x bins occupy consecutive ranges in the sorted point array.
Replace separate per-bin batches with one range ending at `bin_offsets[bin + run]`.
Stop each run at the periodic seam, where the bin IDs stop being contiguous.
This reduces short batches and barriers, especially for sparse input.
It does not change the point traversal order.

**`double`: double-buffered weights, on top of `runs`.**
Allocate two sets of staged rows and alternate between them.
Remove the barrier after accumulation because the next batch writes the other buffer.
The staging barrier remains. Shared storage approximately doubles.
This did not improve the four-case result and worsened the dense screening result. Reverted.
The session did not isolate every hardware cause of this result.

**`smallz`: smaller z tile, on top of `runs`.**
Set `TILE_Z=4` and `GROUP_Z=1`, keeping 128 threads per block.
The smaller tile reduces cells per thread but increases repeated staging and the number of tiles.
The measured result was worse. Restore both header constants.

**`binz`: bin-level periodic z rejection, on top of `runs`.**
Compute once per z bin whether its support can intersect this warp's z group.
Normalize the group-to-bin offset across the periodic seam.
Use the shortened final bin's actual extent in the coverage test.
Guard only `accumulate_batch`. Every thread still participates in staging and both block barriers.

This moves the rejection decision outside the point loop.
Unlike `zskip`, it does not add a coverage branch for every staged point.
The final implementation also updates the barrier comment to say that staging and accumulation may be conditional.

### Staging and loop experiments

**`gather`: write each staged destination once.**
For each local cell, compute its periodic support offset.
Select its weight with an unrolled comparison against all six kernel coefficients.
Write the selected weight, or zero, once instead of clearing the row and scattering coefficients afterward.
This reduced some work but added coefficient-selection instructions.
Sparse and dense results regressed. Reverted.

**`clear-outside`: avoid zero stores to covered cells.**
Keep the original coefficient scatter.
Only clear cells outside the support, using periodic offset checks in the clear loop.
The extra checks did not yield a general improvement. Reverted.

**`unroll2`: request two-way unrolling.**
Add `#pragma unroll 2` to the original accumulation loop.
The measurements did not justify keeping the directive. Reverted.

**`batch64`: stage 64 points.**
Increase `STAGE_POINTS` from 32 to 64.
Replace the single staging round with a strided loop over `(point, dimension)` slots.
Temporarily remove the assertion that all staging slots fit in one round.
The larger batch reduced some overhead on clustered input, but sparse time increased to 2.626 ms.
Restore the 32-point batch and the original assertion.

### Warp-ballot experiments

These trials tested exact z coverage once per batch rather than loading and testing it serially for every point.
One lane tests each staged point's z weights for its warp's output group.
`__ballot_sync` produces a 32-bit mask of points with a nonzero contribution in z.
All trials preserve increasing point order among accumulated points.

**`ballot`: iterate set bits.**
Use `__ffs(mask) - 1` to select the next point.
Clear the lowest set bit after each iteration.
This helped uniform and sparse input, but dense time increased to 10.193 ms. Reverted.

**`ballot-linear`: test mask bits in a linear scan.**
Keep the ordinary increasing `j` loop and skip points whose mask bit is clear.
Dense improved relative to `ballot`, but remained slower than the baseline at 8.833 ms. Reverted.

**`ballot-unroll`: unroll all 32 mask tests.**
Use a fixed 32-point loop with full unrolling. Mask bits suppress nonexistent or uncovered points.
This produced the fastest uniform screening result, 11.355 ms.
It still regressed sparse and dense, so it was not retained.

No workload-specific selection between masked and unmasked accumulation was added.
The precise instruction and scheduling causes of the dense regressions were not isolated.
They should not be presented as proven solely from these timings.

### Geometry experiment

**`two-warps`: smaller z tile with the original group depth.**
Set `TILE_Z=4` while keeping `GROUP_Z=2`.
This creates 64-thread blocks rather than the first round's 128-thread small-z variant.
Use multiple staging rounds because 96 staging slots do not fit in 64 threads.
All four screening times regressed. Restore the original tile, staging loop, and assertion.

### Layout experiments

**`transpose`: make point index contiguous.**
Change the staged arrays from `[point][local_cell]` to `[local_cell][point]`.
Initially use x/y stride `STAGE_POINTS + 2`, unpadded z stride `STAGE_POINTS`, and 16-byte array alignment.
Keep the scalar-looking accumulation loop and let the compiler use wider loads.
This was the first second-round candidate with promising results across all four workloads.

**`transpose-z`: transpose only z.**
Restore x/y to their old layouts and keep the z transpose.
This reduced the source change, but uniform time returned to 15.779 ms.
The full layout change was more useful.

**`transpose-odd`: use x/y stride `STAGE_POINTS + 1`.**
Restore the full transpose, but use an odd float stride.
This keeps bank padding but does not keep each row aligned for wide vector loads.
Uniform and sparse results were weaker than the aligned layout.
The favorable dense screening result was not sufficient to select this variant.

**`transpose-four`: use x/y stride `STAGE_POINTS + 4`.**
Use 36-float x/y rows and explicit 16-byte alignment.
Keep z rows at 32 `float2` values.
The x/y padding spreads cells across bank groups while preserving row alignment.
Z needs no equivalent padding because all lanes in a warp read the same z group.

**`transpose-unroll4`: add an unroll directive to the aligned layout.**
Uniform and sparse times were essentially unchanged.
The single clustered and dense measurements did not establish an additional benefit.
Remove the directive to minimize the final diff.

**`final-layout`: retain the layout, simplify its interface.**
Replace temporary flat pointer/stride indexing with typed two-dimensional array parameters.
Pass the point index explicitly to `stage_tile_weights`.
Define `WEIGHT_STRIDE = STAGE_POINTS + 4` once.
Update comments to describe the current layout, not the experiments.

The final layout is:

```cpp
__shared__ __align__(16) float kx[TILE_X][WEIGHT_STRIDE];
__shared__ __align__(16) float ky[TILE_Y][WEIGHT_STRIDE];
__shared__ __align__(16) float2 kz[TILE_Z][STAGE_POINTS];
```

The final accumulation loop still visits points in increasing order and performs the same arithmetic.
There are no explicit vector casts, per-point masks, new barriers, or new kernel launches in the retained change.
